## 一、结论

**Go/No-Go：No-Go（规格层）**

模型骨架（`Plan` / `Point` / `JitterProfile` / `RunSession`）成立，核心链路在 Android 上无平台级死路（`dispatchGesture` API 24+ + 悬浮窗 + 前台服务）。但**当前规格不能直接进入实现**：6 个 P0 集中在「字段语义、目标 App 边界、状态机闭环、急停可靠性、空方案、时间轴定义」，不修会直接导致建表返工、验收写不出来、上线后出现「停不下来 / 点错 App」。

进入实现的门槛：6 个 P0 修复 + Spike 1/2/3 通过。

### 维度评分

| 维度 | 结论 | 关键理由 |
|---|---|---|
| 技术可行性 | 黄 | 核心 API 可用；Android 13+ 通知权限、14 FGS 类型、侧载无障碍限制、锁屏息屏、厂商保活均影响 |
| 关键假设 | 红 | 「比例坐标解决横竖屏」「通知栏停止可靠」「热区=触控目标」「总时长看门狗」都站不住 |
| 架构合理性 | 黄 | 四实体方向对；但双写状态、缺 `target_package`、缺 AppSettings、快照生命周期未定义 |
| 安全与误操作 | 红 | 无目标 App 守卫；急停可能被「隐藏」或通知权限干掉；点错 App 无防护 |
| 可测试性 | 红 | 间隔语义、抖动分布、看门狗时钟、孤儿判定均无可观测定义 |
| 范围与排期 | 黄 | 范围收得紧，但截图仍有广场/录方案/滑动/导入，v1 实际不小 |
| 运维与交付 | 黄 | 缺 `schema_version`、导入校验、权限引导、日志与迁移 |
| 合规与风险 | 红 | Play 对无障碍自动化有专门政策；游戏 ToS；「防检测」是高风险表述 |

## 二、P0（阻塞实现）

### P0-1｜`auto_skip` 语义未定义，很可能根本不是 Plan 字段

- **位置**：§2 ER、§3.1、§7.1 保存面板、图 1
- **问题**：全文只有「自动跳过（图 1 开关）」。图 1 中它位于「我的方案（1/10）」列表内，旁边是编辑/删除/启停图标，版式更像**方案名或方案级启停**，不是全局设置。§7.1 又写「防检测与首页开关联动」，但首页开关是「自动跳过」——两个功能疑似混淆。
- **影响**：无法写校验与验收；若是广告跳过则缺整个规则引擎；若是方案启停则缺 `Plan.enabled`；将来迁移必返工。
- **建议**：先删 `auto_skip`，三选一：
  1. 方案启停 → `Plan.enabled`（默认 true）
  2. 全局广告/弹窗跳过 → 独立 `AutoSkipRule` 实体（目标包、匹配条件、动作、超时、总开关）
  3. 运行中失败跳过 → `RunSession` 策略或 `Point.skip_on_failure`
- **验证**：每种解释写 3 条验收；写不出来说明它还不是一个字段。

### P0-2｜缺少目标 App 身份，点错 App 无法防护

- **位置**：§3.1、§3.2、§5、§6
- **问题**：`Plan` 无 `target_package`，`RunSession` 无前台包名。方案只记坐标，不记「给哪个 App 用」。
- **影响**：用户切到微信/设置/安装器/权限弹窗时脚本仍可能继续点——最严重的误操作路径。
- **建议**：
  - `Plan.target_package` 必填（v1 不做「任意 App」）
  - `RunSession` 记 `target_package` + `last_foreground_package`
  - 启动前要求目标 App 在前台
  - 监听 `TYPE_WINDOW_STATE_CHANGED`，包名不符立即 `PAUSED`（`TARGET_MISMATCH`）
  - 系统设置、安装器、权限控制器、桌面加入硬阻止名单
- **验证**：两个测试 App 来回切；运行中按 Home；打开系统设置；断言下一次点击前已暂停/停止。

### P0-3｜`Plan.status` 与 `RunSession.status` 双写，状态机不闭环

- **位置**：§3.1、§3.4、§5 两张状态图、C6、§6、§9
- **问题**：
  - 两处都有 `RUNNING`，两个写者必然漂移
  - `Plan.status` 无 `PAUSED`，会话暂停时方案仍显示运行中
  - C6 只约束 `RUNNING`，**未约束 PENDING/PAUSED** → 可先暂停 A 再启动 B，两套点位并存
  - 孤儿清理排在 v1.5，但 v1 的 C6 已依赖「能清掉旧 RUNNING」，进程被杀后永远锁死
  - `stop_reason=KILLED` 无对应状态
  - 缺 `PENDING→STOPPED/FAILED`、`PAUSED→STOPPED/FAILED`、旋转暂停、权限丢失
- **依据**：Android 13 Task Manager 停止 FGS 时**不给应用任何回调**，只能下次启动对账。
- **建议**：
  - `Plan.status` 只保留 `DRAFT/SAVED/ARCHIVED`；运行态唯一来源是 `RunSession`
  - `Plan.active_session_id` 可空、派生
  - C6 改为「全局最多 1 个非终态会话（PENDING/RUNNING/PAUSED）」
  - 补完整状态转移表；`KILLED` 映射到 `STOPPED` 或独立状态
  - **孤儿对账提前到 v1**
- **验证**：`adb shell am force-stop` 后重启无 RUNNING；暂停 A 后启动 B 被拒或 A 被终止；旋转/撤销权限后进入正确终态。

### P0-4｜三处急停中两处不可靠，「隐藏」还会移除唯一可靠入口

- **位置**：§6、图 2「隐藏」、C10/§7.1
- **问题**：
  - Android 13 用户拒绝 `POST_NOTIFICATIONS` → FGS 通知不出现在抽屉，通知栏「停止」直接消失
  - Android 13/14 FGS 通知可被划掉；**Android 14 连 `setOngoing(true)` 也不再阻止划掉**
  - 悬浮窗「隐藏」后若通知也没了，只剩看门狗——可能几小时后才触发
- **影响**：正是产品最怕的「怎么都关不掉」，属安全红线。
- **建议**：
  - 增加「隐藏也隐藏不掉」的常驻停止小悬浮球/停止条
  - 运行前要求通知权限，拒绝则明确降级并警告
  - 通知被划掉时用 `deleteIntent` 重新发
  - 增加无障碍快捷方式 / 音量键急停作为备用
  - 看门狗改为「无进度」判定
- **验证**：拒绝通知权限、划掉通知、点「隐藏」、撤销悬浮窗权限，四种情况分别测「2 秒内能否停止」。

### P0-5｜点位数=0 / 全部禁用没有不变量

- **位置**：§5 C1–C11、§7.1 公式、§3.2 `enabled`
- **问题**：无「至少 1 个 enabled 点位」约束；公式未声明只统计 enabled。
- **影响**：单轮时长 0，看门狗退化为 60s；会话是 `FINISHED` 还是 `FAILED` 无法判定；导入文件可构造该状态。
- **建议**：新增 C12「保存/启动要求 ≥1 个 enabled 点位」；Σ 只遍历 enabled；全禁用时禁用「开始」并说明；禁用点位保留 `seq` 但执行时跳过。
- **验证**：0 点位保存/启动、全禁用保存/启动、导入全禁用方案，四种都应有明确拒绝。

### P0-6｜时间轴语义、公式、示例三处不一致

- **位置**：§3.2、§7.1、图 4
- **问题**：
  - `click_interval_ms` 未定义是「抬起→按下」（gap）还是「按下→按下」（period）
  - 公式 `(n-1)×interval + n×press + delay` 是 **gap 语义**
  - §7.1 例子「3 按钮 × 800ms → 单轮 2.4s」漏了 `3×75ms` 按压，按公式应为 **2.625s**
  - `delay_after` 定义是「本点结束→下一点开始」，例子却像把它当总周期
  - 最后一轮是否执行 `delay_after`、轮与轮之间是否另加间隔，均未定义
- **建议**：用时间轴定死：第 n 次按下 `t`、抬起 `t+press`、下一次按下 `抬起+click_gap`、下一点按下 `本点最后一次抬起+delay_after`。建议字段改名 `click_gap_ms` / `point_gap_ms`。明确末尾延迟与轮间间隔。修正例子，写表驱动单测。
- **验证**：1/2/3 点位 × `click_count=1/3` × `delay=0/800` 表格，实测对比公式。

## 三、P1（需修复，不阻断开工）

| 编号 | 问题 | 建议 |
|---|---|---|
| P1-1 | 抖动与范围未闭合，可能产生负数/越界 | 补齐各字段范围；统一 `effective = clamp(base+jitter, min, max)`；位置抖动换算 px 后夹热区；明确取整与分布；`jitter_seed` 只承诺参数序列可复现 |
| P1-2 | C4 把贴边按钮判死，但贴边是真实需求 | 允许 `anchor` 中心在 `[0,1]`，运行时热区与屏幕求交；贴边给提示而非拒绝；补宽高范围 |
| P1-3 | 「比例坐标解决横竖屏」被高估 | 只保证相对位置，不保证同一控件；记录 `benchmark_rotation/display_bounds`；方向不一致拒绝启动；C8 补 `PAUSED_REASON=ROTATION` |
| P1-4 | 看门狗在极端值下失真，暂停计入超时 | 改「无进度看门狗」：`last_progress_at` + 最大允许间隔 `max(2×最大预期间隔, 30s)`；暂停冻结；总时长另设硬上限（如 2h）；预估时长只用于展示 |
| P1-5 | 快照粒度/版本/删除后历史未定义 | 加 `snapshot_schema_version` + `engine_version`；快照含 plan_name/target/loop/jitter/点位/display；方案软删、会话保留引用快照；`plan_version` 只做 UI 提示 |
| P1-6 | Android 13/14 权限与分发路径未建模 | 先定 OS 矩阵与分发方式；补权限引导清单；targetSdk 34+ 用 `specialUse` 并备审核说明；侧载加「允许受限设置」引导 |
| P1-7 | 长跑缺「亮屏/解锁/前台」前置条件 | 运行前查 `isInteractive()` + Keyguard；加 `KEEP_SCREEN_ON` 或受控 WakeLock；息屏/锁屏立即暂停；30 分钟提示写清「必须亮屏且目标 App 前台」 |
| P1-8 | 注入失败/用户触摸取消无策略 | 失败分类（`DISPATCH_REJECTED`/`USER_CANCELLED`/`PERMISSION_LOST`/`SYSTEM_BUSY`）；每点重试 1–2 次；连续失败 N 次才 `FAILED`；记 `error_code` |
| P1-9 | 缺可观测字段，C6/C8/C10 无法验收 | 补 `last_progress_at`/`error_code`/`display_w/h`/`rotation`/`foreground_package`；v1 加环形事件日志；时钟抽象（`elapsedRealtime` 算时长） |
| P1-10 | 导入导出、配额、DRAFT 规则不完整 | 加 `schema_version`；导入全量校验 + 大小上限 + 原子事务；配额只统计 `deleted=false` 的 `SAVED`；明确 DRAFT 去留；若图 1 开关是启停则加 `Plan.enabled` |
| P1-11 | `seq` 重排会瞬时冲突，缺点位数上限 | 事务 + 临时偏移；或改 `sort_key` 派生显示序号；补每方案最大点位数 |
| P1-12 | 防检测是全局还是方案级，存在双源 | 定「全局默认 + 方案覆盖」优先级，或全局唯一；快照存生效值 |

### P2（建议优化）

- **P2-1** 默认值与截图不一致（文档 800ms vs 截图 1000ms）；截图有不做的入口（广场/录方案/滑动点/撤销），v1 应隐藏而非留死控件。
- **P2-2** 「热区=44~48dp 最小触控目标」论证错误：注入点击没有手指，热区不会放大目标按钮，且只在 20:9 屏幕成立。
- **P2-3** `jitter_seed` 不能复现实际时序；`benchmark_w/h` 不足以描述旋转/密度/显示区；`created_at` 不适合作时长；`ClickEvent` 放到 v1.5 会让 v1 无排障数据。
- **P2-4** 「防检测」作为能力名有合规与可信度风险，建议对外改「参数随机化」，只描述行为不承诺绕过。

## 四、技术验证点（Spike）

| # | 目标 | 通过标准 | 不通过退路 | 预计 |
|---|---|---|---|---|
| 1 | 手势时序与串行化 | `press=75ms` 实测 60–90ms；`gap=1000ms` 实测 950–1050ms；120ms 连点不丢点；不互相取消 | 提高最小间隔、降 `click_count` 上限、下线连点预设 | 1–2 天 |
| 2 | 坐标权威与旋转/分屏 | 中心点误差 ≤1px；边缘点不被手势区吞；旋转后仍命中同一控件（大概率不通过） | 按方向存坐标；旋转后强制暂停并要求重录 | 1 天 |
| 3 | 急停可靠性 | 任一情况下 1 次操作、≤2s 内停止，无残留点击 | 常驻悬浮停止球、无障碍快捷方式、音量键急停 | 0.5–1 天 |
| 4 | 后台存活与息屏锁屏 | 息屏/锁屏立即暂停；清后台后会话标记终态，无「窗口还在服务已死」 | keep-screen-on/WakeLock、电池优化引导、缩短单次上限 | 1 天 |
| 5 | 孤儿对账与状态机 | 无残留 RUNNING；不重复点击；悬浮层被清理 | 启动时把所有非终态标 KILLED + 「清除卡死会话」按钮 | 0.5–1 天 |
| 6 | 目标 App 守卫 | 包名变化 ≤200ms 暂停；系统设置/安装器/权限控制器被硬阻止 | 白名单 + 每次点击前检查前台包名 | 0.5 天 |
| 7 | 侧载/OS 矩阵/FGS | 安装到可运行 ≤3 步；`startForeground()` 不抛异常 | 云手机预装/企业分发，或明确只支持旧系统 | 1 天 |
| 8 | 极端配置与导入 | 无 ANR/崩溃；预估偏差 ≤10%；非法导入 100% 拒绝 | 降上限、加总时长硬上限、导入前全量校验 | 0.5 天 |

**遗留不确定性**：云手机 Android 7.x 短按可靠性；目标 App 横竖屏是否重排；各厂商清后台策略；Android 13/14 通知被拒/划掉后的 FGS 表现；息屏时注入是否落到锁屏；悬浮窗权限撤销能否及时感知；侧载 Android 13+ 无障碍开启步骤；目标游戏反作弊是否检测注入（无法保证）；用户对「间隔」是 gap 还是 period 的直觉。

## 五、评审认为原文站不住的判断（重要）

| 原文档判断 | 评审意见 | 验证方式 |
|---|---|---|
| 「清掉后台悬浮窗仍在、脚本还在动，机制上必然」 | **不必然**。悬浮窗属于应用进程，进程被杀窗口即消失；FGS 只提高存活率。写成「必然」会误导孤儿清理与用户预期 | `am force-stop`、划最近任务、Task Manager 停止，分别观察 |
| 「比例坐标顺手解决横竖屏」 | 只解决相对位置，不解决语义位置。App 重排后同一比例可能指向别的控件 | 竖屏录制、横屏运行，看是否命中同一按钮 |
| 「0.12×0.05 ≈ 44~48dp 是最小触控目标，所以容错」 | **论证错误**。注入点击没有手指，44dp 是给人的 guideline；热区不放大目标按钮，只定义抖动夹取范围，且只在 20:9 成立（16:9 下 0.05 高仅约 35dp） | 16:9 与 20:9 各放 0.05 高的点，测命中率 |
| 「看门狗 = 总时长×1.5+60s」 | 极端值下是 6.7–49.5 小时，失去意义；短任务又被 +60s 放太松；暂停时间计入；防不了进程死亡与卡步 | 卡死、暂停、杀进程三种场景 |
| 「通知栏常驻停止」是可靠 kill switch | 只能算辅助：Android 13 拒绝通知权限就不显示；13/14 可被划掉，14 连 ongoing 也不阻止 | 拒权限、划通知、隐藏悬浮窗 |
| 「不静默自启」是平台保证 | 是产品选择，不是平台保证。`START_STICKY`、系统重绑无障碍服务、厂商自启动都可能让进程回来 | 杀进程后观察系统是否重绑 |
| 「Android 7.2 基线」 | 从截图水印推断，不是正式版本号，不能据此定 minSdk | 查目标云手机 `ro.build.version.sdk` |
| 「`auto_skip` 是 Plan 字段」 | 图 1 版式更像方案列表项，很可能是误读出来的字段 | 确认图 1 该行交互 |
| 「防检测是有效能力」 | ±5ms/±3px 很可能被系统调度噪声淹没，随机化 ≠ 绕过检测 | 采 1000 次实际时序看分布 |
| 「孤儿清理放 v1.5 可以」 | **不行**。v1 的 C6 已依赖「能清旧 RUNNING」，崩溃一次就锁死，对账必须在 v1 | force-stop 后重启看能否再启动 |

## 六、进入实现前必须定的 4 件事

1. **`auto_skip` 到底是什么**：方案启停 / 全局广告跳过 / 失败跳过。**定义不出来就先删字段。**
2. **方案是否绑定目标 App**：`target_package` 必填，还是允许任意 App。建议 v1 必填。
3. **急停的可靠载体**：不能只靠通知栏，必须有「隐藏也隐藏不掉」的悬浮停止入口。
4. **OS 矩阵**：minSdk / targetSdk；只服务云手机 Android 7.x，还是要覆盖 13/14/15。

## 七、MVP 裁剪建议

**必须保留**：单目标 App 方案；增删排序点位；四个时间参数 + `enabled`；`loop_count` 1..99；保存；开始/暂停/继续/停止；**常驻可见的停止入口**；权限自检；前台目标校验；持久化 + 启动孤儿对账；无进度看门狗；旋转暂停；息屏/锁屏暂停；最小会话日志。

**第一版必须砍掉**：方案广场；滑动点开关；录方案；撤销；三套预设；导入方案；跨设备；防检测配置面板（随机化引擎保留固定默认值）；`ClickEvent` 明细表；历史会话 UI；方案复制分享。

砍完仍满足核心闭环：**一个 App、一组点位、跑 N 轮、随时能停**。
